# Changelog

All notable changes to this project are documented in this file.

## [Unreleased]

### Fixed
- The Read the Docs build uses the latest Rust toolchain (the dependencies of the Rust extension need Rust >= 1.85).

## [0.7.0] - 2026-10-07

### Breaking changes (summary)
This release reworks the package step by step; the detailed entries are listed below. The most important changes
when migrating from 0.6.0:

| Before | Now |
| --- | --- |
| `from fibomat import Sample, Site, Pattern` | `from fibomat.layout import Layout, Site, Pattern` (`Sample` is renamed to `Layout`, no compatibility aliases) |
| `fibomat.layout` (groups, lattices) | `fibomat.arrangements` (`Group`, `Lattice`, ...; `layout_elements()` is `arrangement_elements()`) |
| `U_('µm')`, `Q_('1 ms')`, `((x, y), U_('µm'))` | `unit('µm')`, `1 * unit('ms')`, `Vector(x, y) * unit('µm')` (dimensioned values are `DimFloat`s, `DimVector`s and `DimShape`s) |
| `sample.export('BackendName')`, backend registry, `BackendBaseMeta` | `layout.export(BackendClass)`: backends are passed as classes, there is no registry |
| `Mill(dwell_time=Q_('1 ms'), repeats=...)` with a position dependent dwell time | `Mill(1 * unit('ms'), repeats)` with a constant dwell time (`DDDMill` and `SILMill` are not supported by the default backends) |
| Pitches given as pint quantities | Pitches of raster styles are `DimFloat`s, e.g. `Curve(1 * unit('nm'), ScanSequence.CONSECUTIVE)` |
| `curve_tools` functions return dicts | typed results (`Intersection`, `CurveIntersections`, `OffsetResult`, ...), enums `CombineMode` and `OffsetDirection` (the old strings are still accepted), `offset(curve, delta, direction)` with a non-negative `delta` |
| Lattices with a `predicate` and several constructors | `Lattice.from_rect`, `from_counts` and `from_boundary` with `fast_axis` and an element callback `element(i, uv, xy, n)` (may return `None`) |
| old `BokehBackend`, `DrawTool` | bokeh 3.8 (`bokeh>=3.8,<4`), keyword arguments only, self-contained HTML, new `MeasureTool` |
| `Text` as a group of shapes | `Text` is a transformable of `Glyph`s; `Text`, `Ring` and `HollowArcSpline` live in `fibomat.composite_shapes` |
| `DimShape.set_unit` | `DimShape.to(unit)` returns a new object (shapes are immutable by convention) |
| `Site` field of view measured from the center of the pattern bounding box | the automatic field of view is the smallest square centered at the site, scaled with `Layout.fov_scale` |

### Changed
- Documentation (`docs/`) rebuilt: pydata-sphinx-theme with search and a version switcher (`docs/_static/switcher.json`, hosted on Read the Docs), the changelog (`docs/changelog.md` includes `CHANGELOG.md`), an auto-generated API reference (`docs/api/`, one page per public package), and all user guide pages and use cases adapted to the new API with spelling and grammar fixes. Interactive bokeh plots of the `examples/` scripts are embedded with the new `fibomat-plot` directive (`docs/_ext/fibomat_plot.py`), which replaces the old `bokeh-plot-link` patching. The stale `docs/src`, `docs/tests`, `docs/examples`, `docs/plots`, `docs/requirements_docs.txt` and other leftovers were removed. `.readthedocs.yml` (Python 3.12, Rust toolchain, no conda) and the `docs` extra in `pyproject.toml` are updated. Build with `make html` in `docs/`.
- `bump2version` renames the `[0.7.0] - 2026-10-07` heading of this file to the new version and date (see `.bumpversion.cfg`).
- Docstring fixes needed for the docs build in `Arc.from_bulge` and `DimLattice`.

- The scripts in `examples/` are adapted to the new API (`Layout`, `Vector * unit('µm')`, `DimFloat` values like `1 * unit('nm')`, explicit imports from `fibomat.layout`, `fibomat.mill`, `fibomat.units`, `fibomat.arrangements` and `fibomat.composite_shapes`, the new results of `curve_tools`, `Lattice.from_counts/from_rect/from_boundary`) and checked by running them and looking at their plots; `ring_shape.py` (which raised an error on purpose) is a working example of a custom shape; the examples of the lattices show the callbacks, empty lattice sites, lattices of patterns and of sites; the smoothing example uses a curve without cusps (cusps cannot be smoothed); the `raster_styles/contour_parallel*.py` examples are only adapted in syntax (`ContourParallel` is not reworked yet). `Layout.add_annotation` accepts every dimensioned transformable (e.g. `DimText`, `DimGroup`), not only `DimShape`s.
- **Breaking:** the lattices are redesigned (`Lattice`, `DimLattice`, `LatticeBuilder`, `DimLatticeBuilder`). Lattices are created with three class methods (the same for both classes): `from_rect(width, height, pitch_x, pitch_y, element, ...)` (all points of an orthogonal lattice which fit in a rectangle; the lattice is centered, points on the edges are included), `from_counts(n_x, n_y, pitch_x, pitch_y, element, ...)` (orthogonal lattice vectors, given number of points) and `from_boundary(boundary, u, v, element, ...)` (arbitrary lattice vectors, all points inside of a shape, which may have holes (`HollowArcSpline`, `Ring`); `origin` is the position of a lattice point, default the center of the boundary; `clip_elements` drops elements which are not completely inside). All have `fast_axis` (`'x'`/`'u'` or `'y'`/`'v'`, enum `FastAxis`): the lattice direction along which the points are numbered first, `center` or `origin`, and `description`. `element` is a shape (copied to every point) or a callback `element(i, uv, xy, n)` with the index `i` of the point, its lattice indices `uv`, its coordinates `xy` (a tuple of floats; a `DimVector` for `DimLattice`) and the number of points `n`, which returns the element or None (no element). The elements are moved (with their pivot) to the points. Lattices have the properties `u`, `v`, `points_uv`, `n_points` and `elements_by_uv` (an object array, None where there is no element) and keep them consistent when they are transformed. `Lattice(elements, points_uv, u, v)` is the (validating) constructor. Removed: `generate`/`generate_rect` (replaced by the methods above), the arguments `predicate` (the order is defined by `fast_axis`), `explode` (arrangements are split when they are exported) and `remove_outliers` (now `clip_elements`), and the dependency on `fill_with_lines` (the points are calculated directly). The builders have `rectangular(nu, nv, pitch_x, pitch_y, center)` instead of `generate_rect`, accept numpy integers as keys, and `to_lattice(sort_by='added'|'row_col'|'col_row')` creates a complete lattice (also with `elements_by_uv`).
- `lattice * unit('µm')` creates a `DimLattice` (the check `isinstance(other, U_)` failed since `U_` is no class anymore), also as `unit * lattice`.
- **Breaking:** `Group`/`DimGroup` (and `ArrangementBase`) are reworked. The elements must be transformable and `Group` accepts only elements without units, `DimGroup` only elements with units (`TypeError` for others; `Group([...]) * unit('µm')` creates a `DimGroup`); `elements` is a tuple (the dependency `frozenlist` is removed), groups have `len`, iteration and indexing and a `repr`; `group * unit` returns `NotImplemented` for other operands (`TypeError`, before `NotImplementedError`) and works with the new unit tags (it checked `isinstance(other, U_)`, but `U_` is no class anymore) and also as `unit * group`. `ArrangementBase.arrangement_elements()` resolves nested arrangements on all levels (before, only one level, so groups of groups of groups yielded groups).
- **The NPVE step and repeat XML format did not change** (a golden master test compares the generated files for 12 layouts with files which were created by the backend before the rework: spots, curves, areas with all scan sequences, outlined styles, several/empty/shared sites, nm units, automatic fov). `StepAndRepeatBackend`, `NPVEMill` and `LineByLineOutlined` are reworked for the new units and API: `NPVEMill` validates its arguments (`dwell_time` and `dose` must be `DimFloat`s: a positive time and a charge, charge per length or charge per area, `repeats` an integer >= 1) and has the properties `dwell_time`, `repeats`, `dose` and `scan_direction`; `LineByLineOutlined` takes `DimFloat`s, checks its enum arguments (`TypeError`) and has properties for the outline settings; the backend has the new argument `approximation_error` (default `0.0025 * unit('µm')`, the former hard coded value) for hollow arc splines, raises `ValueError` instead of a bare `RuntimeError` for polygons with less than three points, writes the file with the encoding declared in the XML (`iso-8859-1`), shows the spot dose warning with `warnings.warn` without color codes (before it raised a `NameError`), and does not save `bitmap_*.png` files into the working directory anymore for `use_bitmap` patterns (which still needs the bitmap backend). `StepAndRepeatBackend`, `NPVEMill` and `LineByLineOutlined` are exported from `fibomat.default_backends.npve`.
- **Breaking:** `Ring`s are exported again (`ring()` passed arguments which `FIBShape` did not accept since the outline was moved to the raster style, and read a removed rotation angle of the ring): the format of the version before that change is restored (class `TRing`, the outline block with the ring thickness, `Angle` 0 or the scan direction of the mill). Shapes of rings with `LineByLineOutlined` use the outline of the style.
- `FEIStreamFile` and `stream_file_impl` are reworked for the new units; the files are identical to those of the legacy implementation (compared for several layouts and all options). Arguments are validated (`n_rep >= 1`, `margin` in [0.1, 1]), `time_low_res='low'` selects 100 ns (every other value, also the default `True`, gives 25 ns with a 16 bit converter; this quirk is kept), the unused code for dimensioned bounding boxes is removed, warnings are real warnings and the file name is created with `pathlib` (before, directories containing dots broke the name). `NPVETxt` writes its `\r\n` line endings on all platforms (before, Windows wrote `\r\r\n`). Both pass the description to the backend.
- **Breaking:** `BokehBackend` is reworked for bokeh 3.8 (`bokeh>=3.8,<4`, tested with 3.8.2). It takes only keyword arguments (`unit` also as unit string or pint unit; `rasterize_pitch` must be a `DimFloat`); `plot()` returns the figure, `fig` is created on demand (`save`, `html`, `show` plot automatically), `show()` opens a temporary self-contained HTML file instead of using bokeh's `show` (which loads bokehjs from the internet). **The saved HTML files are self-contained** (`save(filename, use_cdn=False)` and the new `html(use_cdn=False)` embed bokehjs, all JavaScript and CSS; verified by a browser test that nothing is loaded from the internet). The dispatch and the splitting of arrangements/texts are done by `BackendBase` (the 150 lines of copied code are removed); legend items are sorted by the site index (not by parsing the label).
- **Breaking:** the plot tool for measuring (`DrawTool`, a TypeScript string compiled with node on every run, and the unused `MeasureTool` experiment built with `bokeh build`) is replaced by one `MeasureTool` (`default_backends/measuretool.ts`): drag to measure distance and angle (shown in the plot unit), a click removes the measurement. The compiled `measuretool.js` is committed and used without node (public `bokeh.util.compiler` cache hook; the monkey patch of `bokeh.util.compiler._bundle_models` is removed); `scripts/build_measuretool.py` compiles the source (replaces `bokeh_build.sh` and the npm project `bokeh-measuretool/` and `bokeh-measuretool.min.js`), a test fails if the compiled file is outdated.
- **Breaking:** `BokehImage(file, pixel_size, center=None)` is a `Shape` with a unitless `pixel_size` (was a `DimShape` with `image_pixel_scale`, which could not be created with the new units); use `layout.add_annotation(BokehImage(...) * unit('µm'))`. `BokehImage` and `StubRasterStyle` have their own modules; `BokehImage` is exported from `fibomat.default_backends`.
- **Breaking:** `SpotListBackend` (and `PatterningDurationCalculator`) take dimensioned values (`base_dwell_time`, `current`: `DimFloat`); the units may be given as unit strings, pint units or `unit('µm')`; `**kwargs` are removed (unknown arguments raise `TypeError`). The positions are absolute (site center added), `parameters['base_dwell_time']` of `save_impl` is a `DimFloat`. With a base dwell time the dwell times are rounded to integers (with a warning if they are not near integers); `dwell_points()` (new) returns the points. `save` raises `ValueError` without points. The default file rounds the dwell times (before they were truncated by `%d`: `1999.9999999` became `1999`) and warns if they are not integers.
- **Breaking:** `PatterningDurationCalculator` is rewritten without the old unit API (and without `typing.override`, which needs Python 3.12): the duration is `number of dwell points * repeats * dwell time` for spots, curves and `LineByLine` areas with a `Curve` line style (`print()`, `table()`, `total_duration`, `durations` with `DimFloat`s); it supports `Mill` (and mills with `dwell_time` and `repeats` settings); the dose based repeats of `NPVEMill` and `LineByLineOutlined` are not supported until the npve backends are reworked. `prettytable` is imported when the table is printed. The registration of the default backends is removed (see above); the plotting backend is replaced by a placeholder raising `ImportError` if its optional dependencies are missing.
- **Breaking:** the backend registry (`fibomat.backend.registry`, `registry.register`/`get`) is removed, and with it the registration of the default backends (the `name` attributes of the backends stay but are not used anymore). `Layout.export`, `export_multi` and `export_with_description` take the backend *class* only (`layout.export(SpotListBackend, ...)`); a name or any other object raises `TypeError`.
- **Breaking:** the metaclass `BackendBaseMeta` is removed (it computed dictionaries of declared and implemented shape methods for every backend class; this is a plain lookup). `BackendBase` finds the shape methods (methods decorated with `shape_type`, in the whole class hierarchy; cached per class) and a backend supports a shape if the method is overridden; the dispatch (including the fallback to the base classes of the shape, e.g. `Polygon` -> `Polyline`) is done by `BackendBase._dispatch`. `implemented_shape_methods` and `shape_methods` are kept (computed on demand). The stubs of unsupported shapes raise `ShapeNotSupportedError` (a `TypeError`, was `NotImplementedError` for the stubs themselves and `ShapeNotSupportedError` for `process_unknown`). `fibomat.backend` exports `BackendBase`, `ShapeNotSupportedError` and `shape_type`.
- **Breaking:** `BackendBase.__init__(description=None)` replaces `__init__(**kwargs)`: unknown arguments raise a `TypeError` (before, a warning was printed and the arguments were ignored); the `description` of the layout is available as `BackendBase.description`. Patterns of composites with `arrangement_elements()` (arrangements, but also `Text`/`DimText`) are split into their shapes by `BackendBase.process_pattern` (before, only arrangements were; a text raised `ShapeNotSupportedError`).
- `Layout(description=None, fov_scale=1.1)` and `Site(dim_center, dim_fov=None, *, description=None, fov_scale=1.1)`: `fov_scale` (at least 1) is the factor by which the minimal field of view is increased if no explicit fov is given. `Layout.create_site` passes the `fov_scale` of the layout to the site (sites added with `add_site` keep their own); both have a `fov_scale` property.
- **Breaking:** the automatic fov of a `Site` is the smallest square *centered at the site* which contains all patterns (patterns are relative to the center of the site), multiplied with `fov_scale`. Before, the half size was measured from the center of the bounding box of the patterns, so patterns which are not centered at the site could stick out of the fov. `Site.fov` raises `ValueError` (was a `RuntimeError` about the bounding box) for an empty site without explicit fov and if the patterns have no extent (e.g. a single spot in the center).
- `layout`: `Site`, `Pattern` and `Layout` validate their arguments (`TypeError`: `Pattern` needs a dimensioned shape or arrangement, a `MillBase` or None and a `RasterStyle`; `Site.add_pattern`/`Layout.add_site` only accept patterns/sites or arrangements of them; `Layout.add_annotation` needs a `DimShape`; `ValueError`: non-positive fov), have a `repr`, and have type hints, docstrings and module examples. `Site.patterns` and `Layout.sites` (new) return copies of the lists. `Site.theta` (new) is the rotation angle of the site.
- **Breaking:** `Layout.export_with_description` (and `plot` with `descr_pattern`) raises `ValueError` if no site matches (as the docstring always said; before, an empty export was returned); the patterns are regular expressions matched with `re.match`; a single exported site ignores `descr_pattern` with a `UserWarning` (was a `print`). `Layout.plot` accepts a `title` argument (before, it raised a `TypeError` for the duplicate keyword). `Site._impl_rotate` lost its private `_allow_any_rot` argument.
- **Breaking:** `Sample`, `Site` and `Pattern` are moved into the new package `fibomat.layout` and `Sample` is renamed to `Layout` (the pattern design for a sample): `from fibomat.layout import Layout, Site, Pattern`. The modules `fibomat.sample`, `fibomat.site` and `fibomat.pattern` are removed, no compatibility aliases are provided. To avoid circular imports (the backends depend on `Site` and `Pattern`, `Layout` on the backends), `Layout` imports the backend registry and the default backends lazily; the default backends are registered on the first export by name or plot. `fibomat.layout` is not imported by `fibomat.shapes`.
- **Breaking:** the package `fibomat.layout` is renamed to `fibomat.arrangements` (`from fibomat.arrangements import Group, Lattice, ...`), `LayoutBase` to `ArrangementBase` (module `arrangementbase`), the method `layout_elements()` to `arrangement_elements()` (also on `Text`, `DimText`, `Glyph`, `DimGlyph`) and the private `_layout_elements()` to `_arrangement_elements()`. No compatibility aliases are provided; the name `layout` is now used for the container of sites and patterns (the former `Sample`, see below).
- **Breaking:** `Text` and `DimText` are no longer `layout.Group`/`layout.DimGroup`; `Text` is a `Transformable` consisting of `Glyph`s (`Text.glyphs`), `DimText` of `DimGlyph`s. Every glyph provides its shapes (`Glyph.shapes`, `DimGlyph.layout_elements()`/`DimText.layout_elements()` yield `DimShape`s). `Text(...)` no longer needs `fibomat.layout`. The strokes of all segments of a glyph are united (no overlapping polygons which would be exposed twice); segments with a common end point are chained, so that they have proper joins; the stroke outline is a `Polygon`, or a `HollowArcSpline` for glyphs with enclosed areas ('O', 'B', ...). `stroke_width` is the total width of a stroke (was the offset on each side, i.e. twice the stroke width). Blank lines, the alignment of lines and empty texts are handled; unsupported characters raise `ValueError`.
- **Breaking:** `Ring` is no `ArcSplineCompatible` anymore; `Ring.to_arc_spline()` (which returned a `HollowArcSpline`) is replaced by `Ring.to_hollow_arc_spline()`. Callers like `raster_styles` must use it (they are reworked in their own steps). `Ring` requires `0 < thickness <= r_outer`.
- `HollowArcSpline` copies its curves, raises `ValueError` (was `RuntimeError`/bare errors, a `print`) for holes outside of the boundary (they were silently kept as holes), a boundary inside a hole and holes which separate the shape; its `area` subtracts the areas of all holes independent of their orientation. `RasterizedPoints` copies the array, validates it and computes the bounding box with numpy; `repeats_applied` keeps the description.
- Rust: new dependency `i_overlay` (stroking).
- `fibomat.shapes` does not import `curve_tools` and `layout` anymore (this fixes the circular imports; `import fibomat.shapes` and `import fibomat.curve_tools` work again). `curve_tools.rasterize` imports `HollowArcSpline` lazily; the backends, lattices and `npve` import the composite shapes from `fibomat.composite_shapes`.
- **Breaking:** `approximate_parametric_curve(param_curve, epsilon, n_samples=2000, description=None)` returns an `ArcSpline` (was `approximate_parametric_curve(param_curve, rasterize_pitch, epsilon)` returning a list of segments). The old modules `monotone_intervals`, `spiral_segment` and `utils` of `curve_tools.biarc_approximation` (arc length rasterization, classification by osculating circles and greedy fitting with sampled error estimates, including debugging plots) are replaced by the algorithm of Meek and Walton: the curve is split at curvature extrema, inflections and points with vanishing velocity, the spirals are bisected until the enclosing condition holds and the bounding arcs are closer than `epsilon`, then biarcs are returned. The distance between the curve and the arc spline is guaranteed to be at most `epsilon` and the algorithm needs milliseconds (all segments of a bisection level are processed with numpy at once).
- `ParametricCurve.to_arc_spline(rasterize_pitch=None, epsilon=None)`: `rasterize_pitch` is deprecated and ignored; the default `epsilon` is `ARC_SPLINE_RELATIVE_TOLERANCE` (1e-5) times the diagonal of the bounding box (was `length / 1000`).
- `ParametricCurve.from_sympy_curve` no longer calls `sympy.simplify` (very slow), uses common subexpression elimination in `lambdify`, creates the third derivative and returns arrays of the right shape for constant expressions and arrays with one element; `try_length_integration` and `integration_timeout` are deprecated and ignored (the arc length is integrated numerically, the former implementation started a separate process). `from_splipy_curve` returns the right shapes for scalar parameters and uses the third derivative; its debugging output is removed.
- `ParametricCurve.rasterize` integrates the arc length with a Gauss-Legendre rule on a fine grid and inverts it with Newton steps (vectorized, 600000 points in well below a second); it returns the parameters of the points at the arc lengths `0, pitch, 2 * pitch, ...`; `add_endpoint=True` appends the end of the domain; `safety` is deprecated and ignored; the `bounding_box` argument of the constructor is deprecated and ignored.
- `Biarc` is a `Shape` (was a plain `Transformable`), so it can be used in patterns (`biarc * unit('µm')`); `to_arc_spline` returns a copy, the description is passed on; arcs are built from the tangent direction (center side) and not from the shorter angle, so biarcs with arcs of more than a half circle are correct; the joint is computed without cancellation; degenerate cases (equal tangents, semicircles) are handled by the general code path; imports are direct (no more dependency on the removed `transformable_base`).
- `Ellipse.to_arc_spline` approximates the ellipse natively with circular arcs through three points (adaptive subdivision, maximal deviation about `ARC_SPLINE_TOLERANCE` = 1e-6 times the smaller half axis) instead of going through `ParametricCurve` and sympy.
- `Rect` stores its center, width, height and the direction of the width axis (instead of an `ArcSpline`): `width`, `height` are exact, `theta` is normalized to [0, 2pi), the corners are always in counterclockwise order (also after mirroring) and `Rect` requires positive width and height. `Circle`, `Ellipse` and `Rect` validate their arguments with `ValueError` (finite, positive sizes).
- `Polyline`/`Polygon` convert the points with numpy (fast for big arrays), reject points with units (`VectorValueError`, the unit was dropped silently), arrays of the wrong shape and fewer than two points; `Polygon.regular_ngon` requires an integer `n` and finite radius; `Polygon.area` uses the arc spline directly. `Circle.from_points` raises `ValueError` for equal or collinear points.
- Shapes import `Shape` and `ArcSpline` directly from their modules; `_impl_*` methods are typed with `Vector`; docstrings and module examples added.
- **Breaking:** `ArcSpline.center` (and the native `ArcSpline.center`) is the center of the bounding box (was the mean of the vertices), so `rotated(..., 'center')`, `scaled(..., 'center')` and group centers of arc splines do not depend on the vertex density anymore.
- `Arc`: `from_bulge` and `from_points` are computed in closed form (no trigonometric formulas with special cases); `from_bulge` raises `ValueError` for a zero bulge or equal points, `from_points` for collinear points; `from_points_center` and `from_points_center_tangent` check that start and end have the same distance to the center (`ValueError`) and give a message if the given tangent is no tangent (`RuntimeError`); `split_at` requires `0 < angle < theta`; `unit_tangent_at` rejects negative angles; the bounding box is computed from the axis angles which are passed by the arc; `mirror` is computed from the angles; type hints, docstrings and a module example added.
- `Line.distance_to_point` returns the distance to the line segment (was the distance to the infinite line); `Line.intersection` returns the `Vector` of the intersection of the two segments or `None` (was an `IndexError` if there is none); `Line.to_arc_spline` does not use the deprecated `clone_with_new_description` anymore.
- `ArcSplineCompatible` is an abstract base class (was a runtime-checkable `Protocol`): classes deriving from it must implement `to_arc_spline` (before, a forgotten implementation was only detected when the method was called). `isinstance` checks still accept every object whose class defines a method `to_arc_spline` (duck typing), but no longer attributes or properties with that name.
- `ArcSpline` validates its vertices: shape (n, 3), finite values, `|bulge| <= 1` (rounding errors up to 1e-9 are clipped) and at least two vertices; errors are `ValueError`. `ArcSpline.area` raises `NotImplementedError` for open curves (was the area of the closed-up curve). `ArcSpline.vertices`, `segments`, `unit_tangents`, `kinks` and `segments_at_vertex` use the native numpy array; `unit_tangents` returns `Vector`s; invalid vertex indices (also negative ones) raise `ValueError`.
- `ArcSpline.bounding_box` uses the native bounding box instead of building one python object per segment. The native box is exact for arcs of at most a half circle (checked against sampled curves).
- `ArcSpline.clone_with_new_description` is deprecated (use `with_changed_description`).
- `fibomat.shapes.spot.Spot`: imports `Shape` directly (`from fibomat.shapes.shape import Shape`), `is_closed` raises `NotImplementedError` with a message, the `_impl_*` methods are typed with `Vector`; type hints, docstrings and a module example added. A non-finite position raises `ValueError` in the constructor (was an error only when the bounding box was requested).
- **Breaking:** `DimShape.set_unit` (which scaled the shape in-place, also the shape object the `DimShape` was created from) is removed; use `DimShape.to(unit)`, which returns a new `DimShape`. `DimShape` objects are immutable by convention. `SpiralRasterStyle` uses `to`, so it no longer modifies the shape of the pattern it rasterizes.
- `Describable.clone` shares the attributes listed in `_shared_attributes` with the clone; `Pattern` shares its mill and raster style with its clones (they are treated as immutable configurations). `Describable` got type hints and docstrings.
- `fibomat.shapes.dim_shape.DimShape`: the unit can be given as string, `pint.Unit` or `unit('µm')` (was `isinstance(unit, U_)`, which fails with the new `U_`); `DimShape(...)` and `set_unit` raise `TypeError` for non-units and `DimensionError` (was `ValueError`) for units which are no lengths. `shape` must be a `Shape` (`TypeError`). `DimShape.pivot` uses the pivot of the underlying shape unless a pivot is set for the `DimShape` itself. Type hints, docstrings and a module example added.
- `Shape.__mul__` works with the new unit tags (`shape * unit('µm')`, was `isinstance(other, U_)`) and passes the `pint.Unit` to `DimShape`. Unsupported operands yield `NotImplemented` (-> `TypeError`, was `NotImplementedError`); units which are no lengths raise `DimensionError`.
- `Shape` derives from `Transformable[Vector, BoundingBox]`; `Shape.area` and `Shape.boundary_length` raise `NotImplementedError` with a message and have docstrings.
- `fibomat.linalg.transformables`: `TransformableBase` is removed (also from `fibomat.linalg`). `Transformable` is now generic (`Transformable[VectorT, BBoxT]`), `DimTransformable` derives from `Transformable[DimVector, DimBoundingBox]`. Arguments of `translated`, `translated_to`, `mirrored`, `transformed` and the `origin` arguments are converted to the vector type of the object before the `_impl_*` methods are called.
- `fibomat.linalg.boundingboxes`: `BoundingBoxBase` is removed. `BoundingBox` is generic over the vector type and `DimBoundingBox` derives from `BoundingBox[DimVector]`. Boxes with and without units cannot be mixed (`TypeError`); `BoundingBox.corners` returns the corners in counterclockwise order (lower left, lower right, upper right, upper left); `from_points` accepts any iterable of vector-likes.
- `rotate(...)`, `scale(...)` validate their arguments (`TypeError` for non-numbers, `ValueError` for non-finite values or a zero scale factor). The `|` operator creates a new transformation chain and no longer modifies its left operand.
- `GeomLine.intersect_at_param` / `intersect_at` raise `ValueError` for parallel lines; `GeomLine.parallel_to` uses the sine of the angle (default tolerance 1e-8) instead of `cos ~ 1` (which treated angles up to ~0.26 degree as parallel).
- `fibomat.linalg.vectors`: `VectorBase` is removed. `Vector` is now generic (`Vector[S]`) and implements all vector logic; `DimVector` derives from `Vector[DimFloat[LengthDimension]]` (components, `mag`, ... are `DimFloat`, `dot`/`cross` return area `DimFloat`). `angle_between` and `signed_angle_between` moved to `vector_functions.py` (still importable from `fibomat.linalg(.vectors)`).
- `DimVector` accepts `DimFloat` components. `pint.Quantity` components are still accepted but emit a `DeprecationWarning`. `DimVector` and `Vector` can no longer be mixed in arithmetic (`VectorValueError`).
- Floating point types such as `np.float32` are accepted as vector components.
- `Vector.__eq__` returns `False` (instead of raising) for non-vector-like operands and `NotImplemented` for non-iterables; vectors are explicitly unhashable.
- `DimVector.close_to` uses an absolute tolerance of 1 pm (independent of the internal unit); `Vector.close_to` of 1e-8.
- Build system changed from meson-python to maturin (`[tool.maturin]` in `pyproject.toml`, stable ABI `abi3-py38`). CI workflows build wheels with `PyO3/maturin-action` instead of cibuildwheel. The `bokeh` build requirement was dropped.
- `offset_with_islands` orients its input itself (islands clockwise, outer curve counter-clockwise) and raises `RuntimeError` for open curves.
- `ArcSpline.visit` passes segment indices starting at 0 on every call (the C++ version kept a static counter).
- `ArcSpline.impl_translate` / `impl_mirror` / `bounding_box` / `center` raise `RuntimeError` for invalid input or empty curves.
- `requires-python` lowered from `>=3.9` to `>=3.8`; added the Python 3.8 classifier.
- **Breaking:** `curve_tools` returns typed results instead of dicts. `self_intersections(curve)` returns a list of `Intersection(position, index_1, index_2)` (was `{'intersections': ...}`), `curve_intersections` a `CurveIntersections(points, overlaps)` of `Intersection`s and `Overlap(start, end, index_1, index_2)`s (was `{'intersections', 'coincidences'}`), `combine_curves` a `CombineResult(boundaries, holes)` (was `{'remaining', 'subtracted'}`) and `offset_with_islands` an `OffsetResult(islands, outer_curves)` (was a dict). All results are `NamedTuple`s, positions are `Vector`s. `HollowArcSpline` uses the new results.
- **Breaking:** the `mode` of `combine_curves` is a `CombineMode` (`UNION`, `INTERSECT`, `EXCLUDE`, `XOR`) and the `direction` of `offset` an `OffsetDirection` (`INWARDS`, `OUTWARDS`, `LEFT`, `RIGHT`); the former strings are still accepted, unknown values raise `ValueError` (before, any string other than `'outwards'` meant inwards).
- **Breaking:** `offset(curve, delta, direction)`: `delta` is the (not negative) distance and `direction` selects the side (before, the sign of `delta` and the orientation of the curve decided); closed curves need a direction, `'inwards'`/`'outwards'` are rejected for open curves, `'left'`/`'right'` refer to the direction of the curve. `offset_with_islands` validates its arguments (closed curves, islands with positive orientation, `delta >= 0`).
- `deflate`/`inflate` offset the original curve by `k * pitch` (no accumulating errors, no code duplication), validate their arguments (`pitch > 0`, `n_steps` an integer >= 0, `distance >= 0`, not both limits, closed curve) and take the number of steps of `distance` with a tolerance (`distance = 3 * pitch` gives three steps). `n_steps=0` returns no curves (was: unlimited steps because of a truthiness check); `SAFETY` is checked against the requested steps.
- `rasterize` is vectorized (no loops over points and segments) and measures the pitch along the curve; the first point is the start of the curve, closed curves do not contain the start point twice, a segment end belongs to the preceding segment. `ParametricCurve`s are rasterized with `rasterize_at`; unsupported objects raise `TypeError` (was `ValueError`/an error caused by a wrong `getattr` dispatch); the pitch is validated. `rasterize_with_const_error` validates its arguments and is exported from `fibomat.curve_tools`.
- **Breaking:** `fill_with_lines` is rewritten as a scan line algorithm: the crossings with the boundary and the holes are computed exactly (lines and arcs split at their extrema) and paired with the even-odd rule, a line on the lower boundary is part of the fill and a line on the upper boundary is not (half-open rule). One of the lines always passes through `seed` (default: center of the shape), for `invert=True` too (the grid was shifted before); rows are ordered from the top (`invert=False`) or the bottom; the pitch and `alpha` are validated. The functions live in `curve_tools.fill`.
- **Breaking:** `fill_with_spiral` returns an analytic `ParametricCurve` of the Archimedean spiral `r = pitch * phi / (2 pi)` which ends on the circumscribed circle of the bounding box (before, the arms had the distance `2 pi * pitch` because of a wrong scaling, the curve was built with sympy and the return annotation was wrong).
- `smooth` is rewritten: the fillet of every kink is found with Newton's method on the offset curves of the adjacent segments (lines and arcs in any combination, convex and reflex corners, open and closed curves); the tangent points must lie on the segments and neighbouring fillets must not overlap, otherwise `NonSmoothableError` is raised (before, such curves silently produced invalid results); cusps raise `NonSmoothableError`; `radius` is validated (`ValueError`), non-`ArcSpline`s raise `TypeError`. Trimmed arcs keep their geometry.
- **Breaking:** `Mill(dwell_time, repeats)` has a constant dwell time: `Mill.dwell_time` returns the `DimFloat` which was passed (was a function of the position, which the class constructed itself) and `Mill` is a `MillBase` and no `DDDMill` anymore. `dwell_time` must be a `DimFloat` with dimension `[time]` (a plain pint quantity, a float or the former `Q_` is rejected with `TypeError`/`ValueError`; the former `isinstance(dwell_time, Q_)` check made `Mill` unusable since the units rework), positive and finite; `repeats` an integer (numpy integers are accepted, `bool` is not) of at least 1.
- The `mill` package has one class per module (`mill_base`, `mill`, `special_mill`, `ddd_mill`, `sil_mill`, `ionbeam`). `MillBase` copies its settings and has a repr with the `repr` of the values; the module imports of `numpy`, `pint` and the beam are removed. `DDDMill` and `SILMill` are only moved, they are not reworked yet (see `TODO.md`).
- `IonBeam`/`GaussBeam` use `DimFloat` (`GaussBeam(fwhm, current, beam_cutoff)`, `std` is a `DimFloat`, `flux_at` returns a `DimFloat` for one beam maximum and `(np.ndarray, unit)` for several, in pA / µm^2) and validate their arguments (positive length/current, integer cut-off, points, length units); `flux_at` accepts vectors and arrays and is vectorized. The beam spots of `nominal_flux_per_spot_on_line` and `nominal_flux_per_spot_in_rect` are those with a distance of at most `beam_cutoff * std` (the rectangular version excluded spots exactly on the cut-off). `IonBeam` and `GaussBeam` are exported from `fibomat.mill` again.
- **Breaking:** the raster styles work with the new units and the constant dwell time of `Mill`: pitches (`Curve(pitch, ...)`, `LineByLine(line_pitch, ...)`) must be `DimFloat`s with dimension `[length]` (`0.5 * unit('µm')`; before, they were checked with the removed `.m` attribute of pint quantities), positive and finite (`TypeError`/`ValueError`). The dwell time is the constant `mill.dwell_time` (no per-point function calls; vectorized with numpy), positions are scaled with `scale_factor`. Styles which need a position dependent mill raise `TypeError` for anything but `Mill` (see `TODO.md`).
- `Curve`, `SingleSpot` and `PreRasterized` build their patterns with numpy only (no loops over points; `Curve` did not use the public API of `RasterizedPoints` but modified its private array); `BACKSTITCH` is vectorized. `PreRasterized` multiplies the weights of the points with the dwell time and repeats the whole sequence `repeats` times; `SingleSpot` does not print anymore and raises `TypeError` (was `RuntimeError`) for shapes other than `Spot`, like `PreRasterized`. `scan_sequence` arguments accept a `ScanSequence` or its string value (`ScanSequence.parse`).
- `LineByLine` validates its arguments (`alpha` in [-pi/2, pi/2], dimension of the line style, ...), fills `HollowArcSpline`s and shapes with `to_hollow_arc_spline()` (e.g. `Ring`) including their holes (before, `to_arc_spline()` was used, which a `Ring` does not provide anymore), creates the `DimShape` of each row directly and returns an empty pattern (not an error) if there is nothing to expose. `Spiral` only uses the constant dwell time of `Mill` now (no other change).
- `scansequence`: `_make_scan_index_sequence` is vectorized (same order and directions as before, except `DOUBLE_SERPENTINE`: its directions now alternate over the whole sequence, so the beam does not jump between two passes for an odd number of lines; for `CROSSECTION` the directions array has now the same length as the indices, before it was `repeats` times longer) and has the correct return annotation; `_apply_scan_sequence` has type hints, uses `Mill(dwell_time, 1)` for the lines (before `DDDMill`, which is not used by `Mill` anymore) and returns an empty pattern for no rows. `ScanSequence` has docstrings which describe each sequence.
- `RasterStyle`: docstrings and type hints (`rasterize` returns `RasterizedPattern`); the commented-out `explode` method is removed. A private module `raster_styles/_helpers.py` collects the shared checks and conversions.
